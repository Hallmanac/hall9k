macOS: not measured. This run had no macOS machine, so there is no process count for the same 20 + 20 ls-remote calls there.
The code comment that says git-remote-https starts the same two helper processes (sh and gh) on macOS, without the leak, is
an assertion from how git's credential helper works, not a measurement. Everything below is Windows.

Harness (not committed; a 20-line console program): in one process, alternate 20 times between two arms, both through
ExternalProcess.Runner with GitForWindowsLauncher.ApplyToCurrentProcess() applied as the daemon does:
  before: GitRemoteAuthentication.Configure(null)        -> git ls-remote origin refs/heads/main refs/heads/before
  after:  GitRemoteAuthentication.Configure(real source: ProjectGitRemoteTokenSource + one ProjectGitHubClient)
                                                         -> git ls-remote origin refs/heads/main refs/heads/after
The owner's ~/.gitconfig has credential.helper = !gh auth git-credential. All 40 calls exited 0.

Reading the table: the two arms differ only in their last ref name, which the kept-token rows below do not show for the
helper-started processes, so the arms are told apart by arithmetic that the table closes exactly:
  - sh.exe and gh.exe started under git-remote-https: 20 sh + 20 gh for "get" and 20 + 20 for "store" = one pair per
    "before" call, none for the 20 "after" calls (a helper that ran for an "after" call would make these 40, not 20).
  - git-remote-https.exe kept its token 20 of 40 times (the 20 "before" calls that started sh); freed 20 of 40 (the "after" calls).
  - tokens kept in total: 181 = 20 x 7 ("before": real git 1, dispatcher 1, git-remote-https 1, two sh, two gh)
                              + 20 x 2 ("after": real git 1, dispatcher 1)
                              + 1 (the one gh auth token the source read, once, for all 20 calls)
  - so kept per call: 7 before, 2 after.
